# 生成控制面威胁模型

## 文档目的

本文档记录生成控制面的信任边界、威胁、已实施控制、审计事件语义和剩余风险。它不是渗透测试报告，也不把单机测试结果解释为生产环境安全验收。

## 保护资产

- 应用、生成任务、工作区、发布结果和数据库资源的租户归属。
- 任务状态、执行轮次、危险工具审批、终态副作用和恢复决策的真实结果。
- 模型配置、凭据密文、Benchmark 证据、用户积分和 Provider 账本。
- 能够说明“谁在何时对哪个资源发起了什么受控操作，结果如何”的审计链。

## 信任边界

| 边界 | 不可直接信任的输入 | 权威事实 |
|---|---|---|
| HTTP 会话 | 路径、查询、请求体、Header、客户端声明的身份 | Session 中的用户编号只是主体索引；当前用户与角色由服务层重新加载 |
| 租户资源 | 请求中的 appId、taskId、userId、tenantId | 应用与任务持久记录及 `TenantAuthorizationService` |
| 平台管理 | 普通租户角色、Controller 方法名或前端显示状态 | `AuthCheck(admin)` 与控制权限矩阵 |
| 内部恢复 | 外部请求、过期 Worker 的本地状态 | 数据库 lease、execution epoch、checkpoint、publication journal 和终态意图 |
| 审计存储 | 业务异常原文、Prompt、请求体、IP、UA、Session、凭据 | 有界枚举、用户编号、资源编号、UTC 事件时间和数据库 `createTime` |

## 受控操作

`GenerationControlPermission` 是提交、查询、取消、危险工具审批、自动恢复、终态重放、Benchmark 管理、模型配置和应用删除的单一权限事实。HTTP 入口通过 `GenerationControlAccess` 同时声明权限、审计资源类型和受信的资源编号表达式。

租户资源的授权仍在服务层依据真实 app/task 归属执行，审计注解不是授权切面。危险工具审批同时要求任务原始提交人和当前 `DEVELOPER` 角色；自动恢复没有 HTTP Controller，主体固定为 `SYSTEM/INTERNAL`。

## 威胁与控制

| 威胁 | 已实施控制 | 剩余风险或后续验收 |
|---|---|---|
| 横向越权，伪造 appId/taskId 操作其他租户资源 | 服务层根据持久归属校验最低租户角色；查询、取消和审批使用任务 tenantId | 需真实多实例攻防和并发降权验收 |
| 角色过期后继续危险操作 | 每次操作重新查询当前租户角色；审批额外校验任务原始提交人 | 需外部身份源与本地租户角色的变更延迟监控 |
| 平台管理员成为混淆代理人 | 平台管理员只在应用删除上具有明示绕过；不能绕过租户成员关系提交生成任务 | 平台内部人员和数据库超级账号仍需职责分离 |
| 重放取消、审批、终态重放或恢复 | 任务状态机、execution epoch、一次性审批、CAS、lease 和专项原子审计共同限制重放 | 通用控制审计是证据而非幂等键，不能替代操作本身的状态门禁 |
| 进程在操作中断，审计结果被伪造 | 操作前以独立事务写入 `STARTED`；只允许单向更新为一个终态；未终结记录表示结果未知 | 通用审计与大部分业务变更不在同一事务，运维不得仅凭 `STARTED` 自动重放 |
| 审计存储不可用时静默执行 | `STARTED` 写入失败时受控操作失败关闭 | 审计数据库故障会降低控制面可用性，需指标、告警和容量基线 |
| 已成功操作因审计终结失败诱导客户端重放 | 已知成功后的终结失败只保留 `STARTED` 并告警，不把成功响应改成失败 | 需对 `STARTED` 长时间未终结建立运维对账视图 |
| Prompt、密钥、异常或 Header 泄露到审计 | 表结构无请求体和自由文本列；结果码为有界值；非安全资源编号改存 SHA-256 | 代码评审仍需防止新注解表达式选取业务敏感字段 |
| 日志注入或故障原文扩散 | 审计失败日志只写 eventId 和异常类型；不写资源值和异常消息 | 应继续扫描审计边界以外的历史日志 |
| 审计表无限增长造成拒绝服务 | 每条事件写入 `expiresAt`，每小时最多删除 500 条，并为到期和资源查询建立索引 | 90 天保留期与批次上限需根据生产写入量做容量压测 |
| 业务代码选择性篡改或删除审计 | 应用边界只暴露新增、STARTED 单向终结和到期批量删除，没有按 actor/app/task 修改或删除方法 | 数据库管理员仍可直接篡改，需最小权限账号、备份和外部不可变存档 |

## 审计事件语义

`generation_control_audit_event` 的每条记录包含 `eventId`、权限名、资源类型/编号、主体类型/用户编号、调用边界、有界结果、开始/完成/到期时间。

- `STARTED`：操作已进入控制边界，结果未知。
- `SUCCESS/OK`：Controller 方法或内部恢复操作已正常返回；SSE 查询表示授权与订阅建立成功，不表示长连接已完整结束。
- `DENIED/BUSINESS_40100|40101|40300`：登录或授权拒绝。
- `REJECTED/BUSINESS_4xxxx`：限流、资源不存在、状态冲突或其他业务驳回。
- `FAILED/BUSINESS_5xxxx|INTERNAL_ERROR`：系统或依赖失败。

通用事件不替代终态重放和 AI 发布的专项审计。专项审计与对应业务变更在同一事务内，能提供更强的重放与发布事实。

## 保留与删除

- 当前固定保留期为 90 天，从 `startedAt` 计算并冻结到每条记录的 `expiresAt`。策略变更不追溯伪造历史到期时间。
- 后台任务每小时按 `expiresAt, id` 有序删除最多 500 条；不进行软删除，避免过期个人标识仍留在业务表中。
- 当前不提供按用户、应用或任务选择性删除的 HTTP 入口；保留期内的审计完整性优先于业务便利性。
- 如需法律保全、延长保留或提前删除，必须新增独立的策略事实、审批和对应审计，不得手工改写事件行。

## 验收边界

当前证据覆盖确定性单元/架构测试与单个 MySQL 8 实例上的新增、单向终结、防二次终结和到期删除。尚未完成真实多实例并发越权攻防、审计库故障注入、长稳容量、外部不可变存档和生产告警验收。
